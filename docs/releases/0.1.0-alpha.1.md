# Tego Next 0.1.0-alpha.1

`0.1.0-alpha.1` is the first usable release of the Tego Next layer-one runtime kernel. It is an
evaluation release, not a production declaration.

## Included

- Single-Main deployment for embedded or standalone systems without an external coordinator.
- Multi-Main deployment backed by PostgreSQL 16 leadership, fencing, durable state, authoritative
  cluster time, takeover, and follower diagnostics.
- Independent Workers using either Worker-to-Main or Main-to-Worker authenticated WebSocket
  connections.
- Thread, child-process, and remote executors behind one executor and execution-binding contract.
- Deterministic `.tego` packaging, inspection, Ed25519 signing, trust verification, installation,
  deployment, status, and immutable artifact storage.
- Kernel-owned plugin reconciliation and component prepare, start, ready, drain, stop, failure,
  restart, upgrade, rollback, and provider-loss recovery.
- Durable task run, status, wait, cancellation, deadlines, idempotency, observation, restart
  recovery, and terminal-result evidence.
- Exact-provider capability routing with inline request/response schemas, permission checks, secret
  isolation, immutable bindings, lifecycle drain, and local/remote topology parity.
- Memory and SQLite support for single-Main composition and PostgreSQL support for multi-Main
  composition.
- Public TypeScript plugin SDK, reusable conformance testkit, CLI, echo plugin, real-process system
  tests, and strict release verification.

## Deployment status

Node.js 26.5.0, npm 11.13.0, and TypeScript 7.0.2 are pinned for development and release evidence.
Production eligibility is explicitly gated on Node.js 26 entering LTS. When that happens, Tego Next
must pass a fresh dependency, API, security, concurrency, recovery, PostgreSQL, and real-process
release review before any production recommendation.

## Security model

- The local control endpoint is a trusted administrative boundary.
- Unix sockets require an owner-private directory and exact owner-only `0600` permissions before
  dispatch.
- Windows named-pipe ACL hardening is not implemented in this alpha.
- Follower path ingress may store immutable content-addressed artifact bytes but cannot mutate
  installation or deployment state. Storage quotas and tenant isolation are deferred.
- Worker credentials authenticate a Worker principal, but layer-two user authentication, business
  authorization, and policy administration are not included.

## Deferred beyond layer one

- HTTP application hosting, REST APIs, GraphQL compatibility, and browser/frontend module loading.
- Enterprise authentication, user/session management, business ACLs, and policy administration.
- Datasource abstraction, PostgreSQL/MongoDB/REST/GraphQL data adapters, CRUD/query/aggregation, and
  relationship expansion.
- Cache, resource catalog, quota service, scheduler, long-running workflow/approval/timer/callback
  products, and business audit UI.
- Tego 1.x compatibility and migration layers.
- General service-component hosting and a separately packaged `@tegojs/node-host` composition root.
- Hardened Windows named-pipe ACLs and artifact-storage quota enforcement.
