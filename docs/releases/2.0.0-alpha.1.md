# Tego Next 2.0.0-alpha.1

`2.0.0-alpha.1` is the first public package contract for the Tego Next layer-one runtime kernel.
It is an evaluation release, not a production declaration. The npm uploads, Git tag, GitHub
prerelease, and OpenSpec archive are not yet complete; they remain pending Tasks 10 and 11.

## Opt-in installation and package set

After publication, install only through the prerelease channel, for example:

```sh
npm install @tego/runtime@alpha
```

The required official-registry state is:

```text
alpha -> 2.0.0-alpha.1
latest -> absent
```

An unqualified install must not resolve to this alpha. All uploads target
`https://registry.npmjs.org/` with public access and `--tag alpha`. The release contains exactly:

- `@tego/cli`
- `@tego/contracts`
- `@tego/drivers-local`
- `@tego/drivers-postgres`
- `@tego/executor-node`
- `@tego/plugin-sdk`
- `@tego/runtime`
- `@tego/testkit`
- `@tego/transport-websocket`

Every package and internal published dependency uses exact version `2.0.0-alpha.1`.

## Included

- Single-Main local and PostgreSQL-backed multi-Main runtime modes, fencing, recovery, and
  leader/follower diagnostics.
- Thread, child-process, and authenticated remote Worker execution behind one task and immutable
  execution-binding contract.
- Deterministic `.tego` packaging, inspection, Ed25519 signatures, trust verification,
  installation, deployment, status, and immutable artifact storage.
- Bounded artifact admission with 256 MiB `maxArtifactBytes` and 4 GiB `maxNamespaceBytes`
  defaults, partial `artifactLimits` overrides, duplicate-free accounting, and stable size/quota
  diagnostics. Local enforcement is atomic within one FilesystemArtifactStore instance;
  PostgreSQL enforcement is transactional for all stores using the same PostgreSQL namespace.
- Deterministic readiness-failure process-tree cleanup and guarded exact PostgreSQL test namespace
  cleanup, including `tego_artifact_namespace_usage` while preserving migration metadata and
  neighboring namespaces.
- Fail-closed Unix and Windows local-control boundaries. Windows requires a protected DACL owned
  by the current user with full pipe access only for the current user, LocalSystem, and
  Administrators, and no request dispatch before the hardened admission barrier.
- Public TypeScript plugin SDK, conformance testkit, CLI, echo plugin, real-process tests, strict
  OpenSpec validation, and a resumable dependency-ordered alpha publisher.

## Release recovery

The release tool separates `--preflight`, `--pack`, `--publish`, and `--verify-registry`. Every
mode repacks the current source tree into the current invocation's artifact directory and writes a
private `release-manifest.json` bound to the target Git SHA, nine-package topology, tarball paths,
and SHA-512 integrities. After partial publication, rerun from unchanged verified source at the
same `targetSha`; the new pack is compared with registry state. `--artifact-directory` selects the
current output directory and does not load a prior release-manifest.json. A package is skipped only
if its complete identity, internal dependencies, new local integrity, `alpha` tag, and absent
`latest` tag match; any conflict fails closed. npm publication does not create Git tags or GitHub
releases.

## Current gates and accepted limits

Node.js 26.5.0, npm 11.13.0, and TypeScript 7.0.2 are the exact release toolchain. Production
eligibility remains gated on Node.js 26 entering LTS and a fresh dependency, API, security,
concurrency, recovery, PostgreSQL, Windows, and real-process review.

The Windows named-pipe ACL implementation has platform-independent tests and a mandatory
`windows-control` job on `windows-2025`, but real Windows execution is not yet verified and remains
Task 10 release evidence. Windows process-tree cleanup uses `taskkill /T` plus refreshed PID +
CreationDate tokens; it does not use a native Windows Job Object launcher. A theoretical
validate-to-termination PID-reuse window, and a descendant created after the final successful
snapshot after all known parents exit, remain accepted non-blocking alpha limitations.

## Deferred beyond Phase 1

Phase 2 and Phase 3 are deferred and out of scope for this release, including HTTP application
hosting, user authentication and business authorization, datasource and cache abstractions,
resource catalogs, scheduler/workflow products, browser/frontend loading, arbitrary-language
plugins, OS-grade sandboxing, production secret-manager drivers, container orchestration, and a
separate `@tego/node-host` package. Tego 1.x compatibility is not provided.

## Verification status

Tasks 1–9 provide executable package, quota, cleanup, Windows-policy, publisher, documentation,
and strict-spec contracts. Fresh exact-SHA local release verification and authoritative GitHub
Actions—including real Windows execution—remain Task 10. Task 11 then performs npm publication,
creates and pushes `v2.0.0-alpha.1`, creates the GitHub prerelease, synchronizes specs, and archives
the OpenSpec change. This document intentionally does not claim those irreversible steps are done.
See [Contributing and plugin authoring](../guides/contributing-and-plugins.md) for the exact local
toolchain and release modes.
